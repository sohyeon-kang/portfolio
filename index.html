팀

종이 기록을 보관하는 모바일 웹

4명이 기획과 프론트엔드·백엔드 개발을 나눠 진행했습니다. 문서 분석, 회상 답변, 추억 카드 저장과 서랍 조회를 연결해 모바일 웹을 만들었습니다.

개인

백엔드 구현과 서비스 통합

  • 인증·문서 분류·정보 추출, 사용자 확정값 관리
  • 카드 저장·조회 연동, 이미지 소유권 검증과 실패 처리
  • AI 제목 검증, 카드 배치·표시 방식 개선

문제와 해결

01저장은 실패했는데, 파일은 남는 문제

문제

카드 저장 중 오류가 나면 업로드한 이미지 파일이 남을 수 있었습니다.

해결

저장 실패 시 잔여 파일을 정리하도록 보완했습니다. 이미지 조회에는 인증·소유권 검증을 연결했습니다.

02답변을 나열하는 AI 제목

문제

회상 제목이 답변을 단순 나열해, 하나의 장면으로 읽히지 않았습니다.

해결

나열형 결과를 검증하고 한 차례 재생성했습니다. 재생성 후에도 부적합하면 직접 입력으로 이어지도록 구성했습니다.

03한쪽에 몰리는 추억 카드

문제

서랍에 카드가 몰리면 개별 기록을 구분하기 어려웠습니다.

해결

기존 카드와 멀리 떨어진 빈 위치를 우선 선택하도록 배치를 변경해, 서랍 전체에 카드를 분산했습니다.

작업 결과

문서 분석 후 정보를 확인하고 추억 카드로 저장해, 연도별 서랍에서 다시 볼 수 있도록 연결했습니다.

배운 점과 아쉬운 점

DUA에서의 경험을 바탕으로 시작 전에 기능을 구체적으로 정리했고, 개발 중 작업이 꼬이는 일을 줄일 수 있었습니다. 시간이 부족해 핵심 기능부터 구현한 뒤 추가 기능을 붙였고, 원하던 기능을 모두 넣어 제출했습니다. 우선순위를 먼저 정하니 마감 부담도 줄었습니다.

해커톤에서 수상하지는 못했습니다. 다른 팀의 결과물을 보며 기존 서비스와 뚜렷한 차이가 부족했다는 점을 느꼈고, 다음에는 어떤 기능을 넣을지뿐 아니라 이 서비스를 선택할 이유도 먼저 고민해 보려고 합니다.

조건 선택 → 추천 코스 → 지하철 이동 안내 · 개인 작업본

팀

현장 조사 기반 부산 여행 서비스

8명이 기획·답사·초기 설계를 진행했습니다. 장소와 이동 조건을 조사해 여행 코스와 지하철 동선을 함께 안내하는 흐름을 기획하고, 추천 API와 화면·지도를 연결했습니다.

개인

화면 재설계와 탐색 흐름 구현

  • 개인 작업본 dua_personal의 와이어프레임·화면 재구현
  • 검색 조건·추천 결과·선택 코스 저장과 복원
  • 지하철 이동 안내 화면, 지도 표시와 로딩·빈 결과·오류 화면 구현

문제와 해결

01화면을 이동하면 사라지는 선택

문제

페이지 이동·새로고침으로 조건과 코스가 초기화되면 같은 검색을 반복해야 했습니다.

해결

검색 조건·추천 결과·선택 코스를 sessionStorage에 저장했습니다. 이전 화면으로 돌아와도 선택한 조건과 코스를 이어서 볼 수 있도록 복원했습니다.

02와이어프레임과 실제 화면의 차이

문제

와이어프레임대로 구현한 뒤 실제 화면을 보니, 구성과 정보 배치를 다시 다듬을 필요가 있었습니다.

해결

여행 조건 선택 → 추천 코스 → 지하철 이동 안내 순서로 화면을 다시 구성했습니다. 각 단계에서 필요한 코스와 이동 정보를 확인하도록 배치를 수정했습니다.

작업 결과

여행 조건 선택부터 추천 코스 비교·장소 상세 확인까지 화면을 연결했고, 화면을 이동해도 선택한 조건과 코스가 유지되도록 했습니다. 지하철 승차·환승·출구 안내는 연결 중이며, 실제 길찾기는 외부 카카오맵으로 이어집니다.

배운 점과 아쉬운 점

처음 해보는 팀 프로젝트라 API 명세와 README, 구체적인 와이어프레임을 충분히 정하지 않은 채 시작했습니다. 개발 중 서로 생각한 기능과 화면이 달라 코드가 꼬이는 일을 겪었고, 시작 전에 팀의 의견을 모아 기능과 화면을 명확히 정하는 시간이 필요하다고 느꼈습니다.

Git으로 작업을 합칠 때 충돌이 나기도 했지만, 직접 사용하면서 점차 익숙해졌습니다. 이 경험을 바탕으로 다음 프로젝트인 기억서랍에서는 개발 전에 기능을 구체적으로 정리했습니다.
